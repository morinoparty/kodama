# 推奨される書き方

## データ取得

- ページ表示に必要なデータはルートの `loader` で取得し、コンポーネントでは
  `Route.useLoaderData()` で参照してください。
- 外部 API の呼び出しは必ずサーバー関数 (`createServerFn`) 経由で行い、
  アクセストークンをクライアントに渡さないでください。

## 非同期 / エラーハンドリング

- 失敗しうる処理は、失敗したときに何が起きるかまで考えて書いてください。
  画面全体が落ちるより、その部分だけ「取得できませんでした」と出せる形が望ましいです。
- ルート単位のエラー表示は `errorComponent`、404 は `notFoundComponent` を使ってください。

## 型

- API のレスポンスは `-types/` に interface を定義し、`as` でのキャストは境界の 1 箇所に閉じてください。
- `any` は使わないでください。どうしても必要な場合は理由をコメントに書いてください。

## Test

- テストは主要な分岐点をカバーする程度に留め、過度な網羅は避けてください。
- テストケースの説明は英語で短く記述してください。

## セキュリティ

- 運営機能は「ログインしているか」だけでなく「ロールを持っているか」まで確認してください。
- クライアント側の表示制御だけで権限を守らないでください。必ずサーバー側でも検証します。
